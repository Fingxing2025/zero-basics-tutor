# 内容审阅与连续记录

本文件在每轮候选教学稿发送前使用。形式检查不能判断学习者会不会陌生、定义是否循环或第一轮是否真正讲到主题；这些项目必须另外审阅。审阅者也会出错，不得把审阅结论描述成数学意义上的完美保证。

## 连续记录

在当前任务 `work/` 中为本次对话选择独有目录。目录里只存本次教学所需的信息：

- 原目标与本轮小目标、阶段顺序、覆盖完成条件。
- 已经在可见对话中发送的内容，以及当前要接着讲的位置。
- 已解释词及含义；学习者主动声明已知的内容及原话位置。
- 主动跳过但尚未解释的内容、待补充项、补讲后返回的位置。

“继续”、沉默或草稿写完都不证明掌握。正在准备的稿件标为候选，不能提前写成“已向学习者讲过”。下一轮以实际可见回复核对记录。状态文件丢失、过期或与对话冲突时不能盲信文件。

## 内容审阅：逐项留下简短依据

审阅对象必须是完整候选稿，包括开头、路线、正文、例子、思考题和最后的进度行。依据使用短引文、段落或行号；不需要展示逐步内部推理。以下各项记录 `已核对`、`不适用` 或 `待修订`。不适用必须有原因；未知不能记为已核对。

1. **新词及前提。** 从头读一遍，记录本轮新引入的概念、缩写、英文、单位、符号和有特殊含义的日常词；为每项定位第一次出现与同句或紧接下一句的解释。前文已解释的项指向实际已发送记录，不能因为学习者说出某词就当作已知。加粗本身不算解释，解释必须说明是什么、在这里起什么作用。
2. **解释依赖。** 检查解释中用到的概念是否已说明；遇到解释甲依靠乙、解释乙又依靠甲的情况，改用具体可观察的过程打断依赖。用同义词或英文译名替换原词不算解释。无需把已清楚的普通词无限拆解。
3. **公式、代码和操作。** 定位每个字母、符号、写法、操作名称和结果的必要解释。例子须有过程与原因，不能只贴公式或输出。区分实际运行的结果与按规则推演的结果，不得编造运行经历。
4. **类比。** 定位每个显式或隐含比喻及紧接的差别说明；说明必须与本次理解相关。只写“这只是比喻”不能替代存在的重要差别。没有类比时可记为不适用，不要为凑项目添加类比。
5. **不考查。** 阅读完整上下文，查找不带问号的索取反馈、要求预测、复述、练习、操作或以反馈为继续条件的写法。程序没有匹配到某种措辞不代表允许。引用学习者问题不应变成再次向学习者提问。
6. **思考题。** 逐题定位题干、分析、明确答案；核对分析确实能从已讲内容得到结论，题目确实围绕主题核心。标签齐全但内容为空、答非所问或依赖未解释知识都需要修订。
7. **推进与覆盖。** 对照用户请求和本轮目标，指出实际完成的讲解与例子；首轮核对终点、路线及主题核心的首次完整呈现。后续轮次核对连接上次位置、补讲后回主线、尊重主动跳过和暂停。不能把必需剩余内容改称可选，也不能因回复太长删除必要解释；可减少本轮不必要的新内容并保留总目标。
8. **事实与表述。** 核对本轮主要事实、计算、条件、类比局限和进度；需要最新信息或来源时按当前环境要求验证。不得把讲过写成学会，不得声称未经实际执行的自动检查或独立审阅。

审阅记录简式示例：

```text
候选稿：draft.md，修订 2（记录修改时间或内容摘要以识别版本）
新词及前提：已核对；“平均数”在第 8 行出现，第 8—9 行通过平分糖果解释。
解释依赖：待修订；第 4 行提前使用“等分”，尚无解释。
公式、代码和操作：不适用；本轮未使用。
类比：不适用；分糖为本题实际场景，没有拿另一件事比拟。
其余各项：逐项填写简短依据，不能沿用这行作为通过记录。
```

## 修订与发布

- 有 `待修订` 项时先改稿；修改可能引入新词、改变段落顺序或破坏答案位置，所以对最终文本重新检查。
- 形式脚本退出码为 0，只能记录“当前脚本未发现已覆盖的形式问题”。内容审阅完成，也只能记录当前审阅结论。
- 最多三轮修订仍有已知问题时，保留稿件并说明实际限制，不声称完美，也不无限重试。
- 若另建外部应用，展示前应由应用实际调用检查并拦截失败稿，而不是让同一个模型自行决定是否跳过检查。仍需承认内容审阅的漏判风险；宁可不展示失败稿，也不能把“没有显示内容”算作成功完成教学。

## 测试范围

`evals/evals.json` 保存真实教学请求与核对标准。`scripts/test_check_lesson.py` 只测试形式检查器识别已知问题的能力；它通过不等于模型在这些教学请求上通过。修改规则后应分别记录模型、请求、实际输出和逐项结果，尤其覆盖“继续”“不懂”“跳过”“暂停恢复”、长对话和含代码公式的场景。没有实际运行就标明未测试，不填写遵循率。
