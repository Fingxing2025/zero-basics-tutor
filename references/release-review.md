# 内容审阅与连续记录

本文件在每轮候选教学稿发送前使用，写成文件时对每个文件使用。形式检查不能判断学习者会不会陌生、定义是否循环或第一轮是否真正讲到主题；这些项目必须另外审阅。审阅者也会出错，不得把审阅结论描述成完美保证。

## 连续记录

记录放在当前任务 `work/` 下本次对话独有的目录里。主会话把同一份学习文档分步交给子会话时，主会话和这些子会话共用这个目录。目录里只存本次教学所需的信息：

- 原目标、教学范围、内容覆盖的完成标准，以及本轮小目标。
- 已完成、当前和待进行的阶段；当前卡点、临时补充后要返回的位置，以及下一步。
- 已解释的词及一句话含义；写成文件时，再写上第一次解释它的文件。
- 学习者主动声明已知的内容及原话位置、可依赖的日常经验；主动跳过但尚未解释的内容、学习者主动提出的疑问。

不维护需要通过考查补全的掌握程度记录。“继续”、沉默或草稿写完都不证明掌握。正在准备的稿件标为候选，不能提前写成“已向学习者讲过”；通过全部检查、即将原样发送的稿件，可以在发送前记为本轮已讲。下一轮以实际可见回复核对记录。状态文件丢失、过期或与对话冲突时，以对话为准。记录只供内部使用，每轮只通过进度行向学习者展示要点；恢复时简短连接当前位置，不因换轮就清空已解释记录。

## 审阅项：逐项留下简短依据

审阅对象是完整候选稿，包括开头、路线、正文、例子、思考题和最后的进度行。每一项记为 `已核对`、`不适用` 或 `待修订`，并用短引文、段落或行号指出依据，不需要展示逐步推理。不适用要写原因；未知不能记为已核对。

1. **新词及前提。** 从头读一遍，列出本轮新引入的概念、缩写、英文、单位、符号和有特殊含义的日常词，包括终点、路线、例子、代码、公式和思考题里的词；为每项定位第一次出现与同句或紧接下一句的解释。加粗本身不算解释，解释必须说明是什么、在这里起什么作用。不能仅凭学历、职业或学习者说出了某个词，就假定学习者会。第一轮还要核对：路线后面阶段的描述里，没有提前用到要在前面阶段正文才解释的词，也没有“这些词后面会讲”。前文已解释的词，指向连续记录里的那一条；写成文件时，名称和含义必须与记录一致，不换叫法，本文件里最多在第一次用到时提醒一句。只是顺带提到的名词，核对它解释到能读懂当前这一处就停，没有展开成与当前目标无关的一整节。
2. **解释依赖。** 检查解释中用到的概念是否已说明；遇到解释甲依靠乙、解释乙又依靠甲的情况，改用具体可观察的过程打断依赖。用同义词或英文译名替换原词不算解释，原样重讲也不算补讲。无需把已清楚的普通词无限拆解。
3. **公式、代码和操作。** 定位每个字母、符号、写法、操作名称和结果的必要解释。例子须有过程与原因，不能只贴公式或输出。区分实际运行的结果与按规则推演的结果，不得编造运行经历。
4. **类比。** 定位每个显式或隐含比喻（包括比喻性的称呼），以及紧接的差别说明；说明必须与本次理解相关。只写“这只是比喻”不能替代存在的重要差别。没有类比时记为不适用，不要为凑项目添加类比。
5. **不考查。** 对照 SKILL.md“绝对不能出现的内容”逐句检查，尤其是最后一段：有没有试探掌握程度、索取反馈、要求预测、复述、练习、操作，或者以反馈作为继续的条件。不带问号的写法也算，程序没有匹配到某种措辞不代表允许。然后找出全文的问号：除了思考题题干和开课前的目标澄清，每一个问号所在的句子都改写成陈述句，包括反问和自问自答的设问。引用学习者的问题时，不能变成再次向学习者提问。
6. **思考题。** 逐题定位题干、分析、明确答案，三者都在同一条回复或同一个文件里；核对分析确实能从已讲内容得到结论，题目确实围绕主题核心。标签齐全但内容为空、答非所问或依赖未解释知识，都需要修订。
7. **推进与覆盖。** 对照用户请求和本轮目标，指出实际完成的讲解与例子，确认必要的铺垫、推理和结果都已展开，没有把解释责任交给学习者，补完基础后回到了当前目标。第一轮核对：给出路线后在同一条回复里开始了第一阶段，讲到了主题本身而不只是前置知识，学习者点名的要求（例如思考题）用到了主题的核心内容。后续轮次核对：连接了上次的位置，补讲后回到主线，尊重主动跳过和暂停。不能把必需的剩余内容改称可选，也不能因回复太长删除必要解释；可以减少本轮不必要的新内容，保留总目标。
8. **事实与表述。** 核对本轮主要事实、计算、条件和类比局限；需要最新信息或来源时按当前环境要求验证。回复以进度行结尾，进度只反映讲过的内容，不把讲过写成学会；不声称未经实际执行的自动检查或独立审阅。
9. **资料引用。** 搜索“第 N 页”“如图”“课件”“原文”“资料里”这类字样，定位每一处提到资料具体内容的地方：提到图的，核对紧接着嵌入了那张图，图上的文字和标签都有解释，而且没有再用文字或字符画重画同一张图、描述页面版式；提到原话、表格或代码的，核对原文已用 `<!-- 原文 -->` 和 `<!-- /原文 -->` 贴入，摘录里只有资料原文、没有教师的话，摘录后面紧接着有讲解。不能出现“详见课件”“见原图”这类让学习者回去看资料的写法。没有学习者提供的资料时记为不适用。

审阅记录简式示例：

```text
候选稿：draft.md，修订 2（记录修改时间或内容摘要以识别版本）
新词及前提：已核对；“平均数”在第 8 行出现，第 8—9 行通过平分糖果解释。
解释依赖：待修订；第 4 行提前使用“等分”，尚无解释。
公式、代码和操作：不适用；本轮未使用。
类比：不适用；分糖为本题实际场景，没有拿另一件事比拟。
其余各项：逐项填写简短依据，不能沿用这行作为通过记录。
```

## 修订

有 `待修订` 项时先改稿；修改可能引入新词、改变段落顺序或破坏答案位置，所以对最终文本重新检查。形式脚本退出码为 0，只能记录“当前脚本未发现已覆盖的形式问题”；内容审阅完成，也只能记录当前审阅结论。
